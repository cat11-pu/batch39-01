# GSB Bugfix Task
## 题面
账号找回这条链路出了两次事故。第一次是同一个重置链接被点了两回，两回都成功，第二回把密码改成了别人想要的值；第二次是用户改了邮箱之后，旧链接还能用，等于换绑没生效。排查下来毛病不少：令牌只存了明文，数据库被读走就等于全部泄露；比较用的是普通字符串相等，长度不同还会提前返回；有效期只在前端展示，后端根本不看；令牌没有和申请时的设备绑定，转发到别的浏览器也能用；同一账号连点五次发送，五个令牌都有效；并发兑换时两个请求同时通过；令牌里的用户编号是自增的，能枚举；过期令牌和未知令牌返回不同错误，等于告诉别人账号存不存在；登出、改密、封禁之后旧令牌没作废；审计里只记了成功，不记失败。reset_ticket_ledger.py 的 ResetTicketVault 要把这些收住：签发时生成高熵令牌、只落摘要、绑定账号与设备指纹，并作废该账号此前所有未用令牌；兑换时先做定长摘要比较，再核对有效期、设备、账号状态，成功后立即标记已用；同一令牌的并发兑换只能有一个成功；错误码对外统一，不区分不存在和已过期；改密、登出、封禁要能主动清空；返回的快照只含令牌编号和状态，不含原文。test_reset_ticket_ledger.py 现在有十五个用例尚未通过，覆盖重放、改绑、明文存储、比较方式、过期、设备不符、批量签发、并发兑换、枚举、状态清理、审计失败记录、快照脱敏、空令牌、超长令牌和跨账号兑换。

## 运行方式
```bash
python -m pytest tests -q
```
