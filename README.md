# GSB Bugfix Task
## 题面
账号系统支持中文和表情符号密码之后，注册和登录开始互相打架。用户设了一个含全角字母的密码，登录时输入半角版本也能过，因为两边都做了兼容规范化却没比较归一后的结果；长度按字节算，一个汉字算三字节，用户以为没超限，实际被截断；表情符号由多个码点组成，按码点计数把半个表情算成一个字符；零宽空格被当成有效字符，两个看起来一样的密码实际不同；形近字母能注册出视觉上完全相同的两个账号；常见密码表只收了英文，拼音和数字组合全漏；连续重复字符的限制只看了 ASCII；密码里包含用户名时没有提示；泄露密码库只比对完整值，加个后缀就能绕过；密码前后空白被静默裁掉，用户下次输入带空格又失败；空字节让底层哈希截断；归一之后长度变化的边界没有重新校验；错误提示直接说密码太短或包含禁用词，等于把策略泄露给攻击者；策略版本升级后老密码没有标记。password_unicode_policy.py 的 PasswordUnicodePolicy 要把策略做在归一之后的字符串上：先做兼容规范化和大小写归一，再按字素簇计数，同时给出码点数和字节数；最小和最大长度、最大字节数分别限制；拒绝控制字符、不可见格式符、方向控制符和未分配码点；形近字母骨架相同且只差不可见字符的密码判为冲突；常见密码、拼音组合、连续序列、重复字符、用户名包含都要检查；泄露库按归一后的前缀哈希比对；首尾空白不静默裁剪，作为普通字符参与校验但给出提示；错误码只分几类，不透露具体规则；结果带策略版本和规则编号。test_password_unicode_policy.py 现在有十五个用例没通过，覆盖全角半角、字节截断、表情计数、零宽空格、形近账号、拼音弱口令、重复字符、用户名包含、泄露后缀、首尾空白、空字节、归一长度变化、错误提示、策略版本和字素边界。

## 运行方式
```bash
python -m pytest tests -q
```
