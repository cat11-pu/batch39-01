# GSB Bugfix Task
## 题面
头像和工单附件的上传接口被渗透测试挑了毛病：把一段脚本改成图片扩展名就传上去了，因为服务端只看扩展名；另一个样本前半段是合法文档、后半段挂着压缩包，我们判成文档直接放行；截断的图片头也被当成图片；UTF-16 编码的文本带 BOM，被识别成二进制；矢量图里带脚本仍然通过；启用宏的办公文档和普通文档扩展名互换没人发现；照片文件末尾追加一段压缩包也能过；声明的内容类型和真实内容不一致时，代码信了声明；零字节文件返回成功；图标和光标的魔数只差一个字节，判断写反；大小写扩展名走了不同分支；双扩展名被当成图片；压缩格式和打包格式的魔数前缀混淆；类型探测只读前四个字节，偏移量算错。attachment_type_triage.py 的 AttachmentTypeTriage 要按魔数、结构特征和声明三方交叉判断：先看真实字节，再看扩展名，最后看声明，三者冲突时按策略拒绝并给出原因；支持常见图片、照片、矢量图、文档、打包格式、办公文档和纯文本，矢量图要单独扫描脚本与外部引用；截断文件按不完整处理；零字节拒绝；双扩展名只看最后一段但要在报告里标出；办公文档要区分是否含宏；结果里给出检测类型、置信度和冲突项。test_attachment_type_triage.py 的十五个用例现在全挂，覆盖扩展名伪装、复合格式、截断、BOM、矢量图脚本、宏文档、尾附压缩包、声明不符、零字节、图标、大小写、双扩展名、压缩格式、偏移和重复检测一致性。

## 运行方式
```bash
python -m pytest tests -q
```
