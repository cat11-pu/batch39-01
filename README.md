# GSB Bugfix Task
## 题面
运营后台接了三家身份提供商，单点登录的状态串开始出问题。用户发起登录后，回调带着状态串回来，服务端只检查它非空，于是同一串能用一整天；状态串没有和浏览器会话绑定，攻击者把自己发起的串塞进别人的回调也能过；回调地址用前缀匹配，自家域名后面再接一段攻击者域名照样放行；授权码能换两次访问凭证；校验串声明的是明文模式，空值也接受；同一个人开两个标签页登录，后一个把前一个的状态串覆盖，先完成的那个报错；状态串放在查询串里被代理日志完整记下；错误回调不验状态串就直接展示错误内容；提供商标识没有参与校验，A 家的回调能拿到 B 家去换；过期时间只写在前端；跨租户的回调混用；换凭证时没有核对最初的回调地址。oauth_state_binding.py 的 OAuthStateBinding 要把这条链路绑死：发起时生成高熵状态串和校验串，状态串绑定会话、提供商、动作、回调地址和过期时刻，校验串只把摘要交给客户端；回调只能消费一次，重复、过期、会话不符、提供商不符、动作不符都拒绝；回调地址必须逐字相等，包括协议、主机、端口和路径，不允许前缀或通配；换凭证时再次核对授权码、回调地址和校验串，授权码成功使用后立刻作废；多个标签页各自独立，不互相覆盖；状态串在日志和快照里只出现摘要。test_oauth_state_binding.py 的十五个用例现在全部失败，覆盖重放、会话不符、前缀回调、授权码二次兑换、明文校验、空校验、多标签、日志泄露、错误回调、提供商混用、过期、跨租户、回调复核、摘要快照和并发消费。

## 运行方式
```bash
python -m pytest tests -q
```
