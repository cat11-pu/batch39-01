# GSB Bugfix Task
## 题面
边缘节点给下载文件拼响应头时出了事故：用户把文件名改成带回车换行的内容，响应里凭空多出一个设置 cookie 的头；另一次是上游回源带回来的头里有折行，拼接时没有展开，浏览器把续行当成了新头；文件名里有 Unicode 的行分隔符，日志看是一条，代理看是两条；同一个响应里出现两个同名但大小写不同的头，CDN 只取了一个；头值前后的空白被保留，缓存键跟着变了；非 ASCII 的文件名没有按规范编码，客户端拿到乱码；逐跳头被原样转发到了下游；Location 头里的地址没有重新校验，跳到了外部域；空值头和缺失头被当成同一种；头名里混入下划线和空格也照发；头数量没有上限，一个响应能塞几千行；多个设置 cookie 的头被合并成一个，属性互相污染；值里的冒号被当成分隔符截断。crlf_header_fence.py 的 CrlfHeaderFence 要提供一套安全的响应头构造：头名只允许规范字符并统一小写，头值拒绝回车、换行、空字节和行分隔符，折行先展开再判定；同名头按语义合并，设置 cookie 必须保持多条；非 ASCII 值按编码规则转换，文件名同时给出兼容写法；逐跳头、代理认证头和内部调试头一律不向下游转发；Location 和内容处置里的地址与文件名要重新走白名单和路径校验；头数量、单头长度、总长度都要有上限；输出顺序稳定，空值和缺失明确区分。test_crlf_header_fence.py 的十五个用例现在是红的，覆盖换行注入、折行、行分隔符、同名大小写、空白、非 ASCII、逐跳头、Location、空值、头名非法字符、数量上限、多 cookie、冒号、长度上限和稳定顺序。

## 运行方式
```bash
python -m pytest tests -q
```
