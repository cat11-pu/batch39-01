# GSB Bugfix Task
## 题面
日志平台把 trace 采样落盘之后，安全审计发现私钥还是被带出来了。我们的脱敏只按行匹配 BEGIN 和 END，可实际日志是按 8KB 分块写的：一个 PEM 块被切在中间，两半都没匹配上；OpenSSH 私钥的 BEGIN OPENSSH PRIVATE KEY 根本不认；JSON 字段里的换行被转义成反斜杠加 n，整段变成一行；PGP 私钥块和证书链混在一起，只删了第一段；同一个块在两条日志里重叠出现，偏移算错后把后面的正常内容也吃了；截断的块没有 END，现在原样保留；测试环境用的假密钥也被一起删掉，回放对不上；大小写混写的标记漏过；块前后的空白和行号没有保持，审计对照困难。pem_span_scrubber.py 的 PemSpanScrubber 要按字节流扫，不假设一行一个块：识别 RSA、EC、OPENSSH、PGP 和证书这几类标记，允许标记前有空白、允许 CRLF，跨块时把未闭合的尾巴留到下一次；闭合后整段替换成固定占位符，同时返回每段的起止偏移和类型；内容里出现嵌套标记按最外层处理；超过大小上限仍未闭合的块要丢弃并记一条告警；调用方传入的白名单指纹命中的块保留原文；输出文本除被替换区间外必须逐字节不变。test_pem_span_scrubber.py 的十五条断言现在全挂，盯着跨块切分、四类标记、转义换行、证书链、重叠区间、截断块、白名单、大小写、空白保持、偏移准确、嵌套、超限、CRLF、连续块和二次处理幂等。

## 运行方式
```bash
python -m pytest tests -q
```
