# GSB Bugfix Task
## 题面
回合制战斗的出手顺序每天都在被玩家投诉。两个速度相同的角色，先后手完全看谁先被加载，换台设备就反过来；加速和减速叠了三层之后，速度值算错，慢的反而先动；带优先级的技能应该插队，现在只改了显示，实际还是按速度排；被眩晕的角色仍然占一个行动位，跳过逻辑写在动画回调里，服务端和客户端各算各的；中途加入的援军被塞到队尾，下一回合才生效；额外行动和延迟行动混在一起，同一角色一回合动了三次；速度为零或负数时排序函数直接抛异常；回合结束时速度修正没有清理，越打越快；双方速度完全一样且没有编号时，顺序随机；回合上限到了之后没有强制结算。turn_speed_order.py 的 TurnSpeedOrder 要产出一份确定的行动序列：每个单位带速度、优先级、状态和阵营，先按优先级分组，组内按有效速度降序，同速按阵营、站位、单位编号依次打破平局；加速减速按乘算叠加后夹到上下限；眩晕、死亡、离场单位跳过但仍占用回合计数；额外行动立即插入当前回合末尾，延迟行动排到指定回合；援军从加入的下一回合开始参与；速度为零或负数按最低速处理并标记；每个回合结束时清理一次性修正；输出行动序列、每步原因和回合边界，同一输入无论加载顺序都得到同一结果。test_turn_speed_order.py 的十五个用例眼下没有一条通过，压同速平局、加减速叠加、优先级插队、眩晕跳过、援军、额外行动、延迟行动、零速、负速、修正清理、随机顺序、回合上限、阵营排序、原因输出和加载顺序无关。

## 运行方式
```bash
python -m pytest tests -q
```
