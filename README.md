# GSB Bugfix Task
## 题面
战斗数值最近对不上，同样一套装备打同一个怪，客户端显示一千二，服务端结算一千零五十。查下来减伤顺序是拍脑袋写的：先算百分比再减固定值，和策划表里的先固定后百分比相反；护盾在减伤之前扣，导致护盾吸收的量被放大；真实伤害仍然吃了护甲；暴击在减伤之后乘，和表里的先暴击再减伤不一致；最小伤害写死为一，但有些技能允许零伤害；四舍五入用了银行家舍入，边界值和表里差一；抗性上限没有夹紧，堆到百分之一百二十之后开始回血；多段伤害每段单独取整，总和对不上；反伤按减伤前的值算，坦克反得太高；目标死亡后溢出伤害没有传给下一个；负数攻击力被当成治疗；护盾类型有多种，物理盾挡不住法术却挡了。damage_mitigation_chain.py 的 DamageMitigationChain 要把结算拆成固定顺序：先算基础伤害与暴击，再按固定值、百分比、护盾、易伤、最终修正依次处理，顺序写在配置里可查；固定值减伤不能把伤害降到零以下，百分比按上限夹紧；护盾按类型匹配，只吸收对应伤害，溢出部分继续走后续步骤；真实伤害跳过护甲和护盾但仍受易伤影响；每段伤害保留小数，最后统一取整，总和与逐段取整的差异单独报告；最小伤害可配置；抗性上限硬夹；反伤基于实际扣除的生命值；目标死亡后的溢出按配置决定是否传递；负数输入拒绝。test_damage_mitigation_chain.py 的十五处断言眼下均不通过，压顺序、护盾放大、真实伤害、暴击、最小伤害、舍入、抗性上限、多段取整、反伤、溢出、负数、护盾类型、易伤、配置可查和总和差异。
