# GSB Bugfix Task
## 题面
内容安全策略的报告端点每天收几百万条，存储和告警都被打爆了。同一个被拦截的地址，因为查询串里带了随机数，每次都被当成新报告；来源文件只差行号或列号，也各存一条；报告只在拦截模式下收，观察模式的样本全丢了；站点标识没有归一，大小写和末尾斜杠不同就分成两个站；畸形报文直接让整批入库失败，一条坏数据拖垮几千条；批量上报里的数组没有逐条校验；未知指令名被静默丢弃，统计时对不上；处置方式字段缺失时默认成拦截，实际可能是观察；被拦截地址里带用户标识和邮箱，原样落盘；采样率固定，热门站点把配额吃光；同一来源在两分钟内重复上报没有合并窗口；报告保留期没有上限，半年前的还在；聚合计数和明细对不上；输出顺序随请求到达顺序变化，无法复核。csp_report_dedup.py 的 CspReportDedup 要做接收端的归一与合并：站点标识统一小写并去掉末尾斜杠，指令名走白名单，未知指令进其他类；被拦截地址去掉查询串和片段，来源文件只保留路径和行列；报告按站点、指令、规范化地址、来源文件生成指纹，窗口内相同指纹只累加计数；观察模式和拦截模式分开统计，处置缺失按观察处理；畸形单条进隔离队列，不影响同批其他记录；地址里的用户标识、邮箱和令牌参数先脱敏；每站点每分钟有条数上限，超出采样并标注；明细保留三十天，聚合计数长期保留；输出按站点、指令、计数降序稳定排列。test_csp_report_dedup.py 的十五个用例全部报错，覆盖查询串、行号差异、观察模式、站点归一、畸形报文、批量数组、未知指令、处置缺失、地址脱敏、采样、合并窗口、保留期、聚合一致、排序和重复上报。

## 运行方式
```bash
python -m pytest tests -q
```
