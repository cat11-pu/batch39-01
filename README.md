# GSB Bugfix Task
## 题面
品牌保护那边抓到一个仿冒站点，域名用的是西里尔字母里长得跟拉丁字母一样的字符，审核同学肉眼看了三遍都没发现。我们现在的域名比对只做了小写化和去掉末尾的点，别的什么都没管：国际化域名转成 punycode 之后没有还原，白名单里写的是明文品牌名，实际比对的是编码串；拉丁字母和西里尔字母混在一个标签里也能过；零宽连接符和变体选择符被当成普通字符；句号写成全角或者表意句号，切出来的标签数量都不对；带尾随点和不带尾随点被当成两个域名；大小写折叠只做了 ASCII；同形数字和字母没有归一；子域名前缀随便加，主域匹配就算通过；邮件地址里的域名部分没有走同一套检查；已经列入黑名单的 punycode 前缀还能注册新变体；域名长度和标签长度没有上限；连字符出现在第三四位这种保留格式没有提示。idn_confusable_guard.py 的 IdnConfusableGuard 要把域名判定做完整：先按统一映射做兼容分解和大小写折叠，识别标签里的文字系统，拉丁字母与西里尔、希腊字母混用直接判高风险；用内置的同形字符骨架表把常见混淆归到同一骨架，再和受保护品牌逐标签比较；punycode 标签要能解码回可读形式并在报告里同时给出两种写法；点号变体统一成普通点，尾随点忽略但要在报告里标注；零宽字符、双向控制符和不可见格式符一律视为可疑；长度、标签数、连字符位置都要校验；结果给出风险等级、命中的规则和归一后的域名。test_idn_confusable_guard.py 的十五条断言现在全部失败，压混写文字、同形骨架、punycode、点号变体、尾随点、大小写、零宽字符、双向控制、数字混淆、子域伪造、邮件域名、黑名单变体、长度上限、连字符位置和报告归一。

## 运行方式
```bash
python -m pytest tests -q
```
