# GSB Bugfix Task
## 题面
注册接口的人机校验上线两周就被刷了。黑产先正常拿一张挑战图，解出来之后把答案票据复制到脚本里反复提交，同一张票据通过了四百多次；票据没有和动作绑定，登录页拿到的能拿去提交注册；有效期写着两分钟，实际只在前端倒计时，服务端不看；难度等级由客户端传，脚本直接传最低档；答错不计数，可以无限试；并发提交时同一张票据两个请求都成功；挑战编号是顺序的，能推测下一张；音频挑战和图片挑战共用一套答案，互相能串；验证通过后没有消费记录，审计查不到；过期票据和伪造票据返回不同错误；签名用了固定密钥，测试环境密钥还进了仓库；空答案和超长答案直接抛异常；同一用户同时开十个挑战，内存不释放。captcha_challenge_ledger.py 的 CaptchaChallengeMint 要把挑战做成一次性凭证：签发时分配随机挑战号，绑定动作、会话和难度档，答案只留摘要，票据带签名和截止时刻；校验先验签名和时效，再比对答案摘要，通过后当场核销，同一票据的并发校验只允许一个成功；答错按票据累计，超过上限立即作废并留痕；难度由服务端按风险决定，客户端传值忽略；音频与图片各自独立答案；过期、伪造、已核销共用同一个错误码；未核销的挑战按数量和时间淘汰；签名密钥从外部注入，导出视图里不出现密钥和答案。test_captcha_challenge_ledger.py 眼下十五个用例全部报错，覆盖重放、跨动作、过期、难度篡改、失败计数、并发、编号可测、音图串用、消费审计、错误码、固定密钥、空答案、超长答案、挑战上限和导出脱敏。

## 运行方式
```bash
python -m pytest tests -q
```
