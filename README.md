# GSB Bugfix Task
## 题面
接入认证换成远程拨号服务之后，计费系统开始收到重复的会话记录。报文里的属性长度字段写成零，解析器原地打转；属性长度超过报文体剩余，读取越界；厂商私有属性里再套一层长度，内外两层没有交叉校验；消息认证器属性重复出现，代码只校验了第一个；代理状态属性被原样回显，攻击者借它追踪链路；隧道属性里的标签和值没有配对；整数属性长度不是四字节也照读；地址属性长度不对时被当成字符串；属性总数未设上限，一条报文能塞几千个；响应认证器用请求的认证器计算，校验永远通过；未知属性被丢弃，导致转发后语义变化。radius_attribute_fence.py 的 RadiusPacketGuard 要按报文结构逐层校验：先验报文长度与属性区是否吻合，再逐个检查类型、长度和值；长度为零或超出报文体剩余立即拒绝；厂商私有属性拆出厂商编号后按内层长度重新校验；消息认证器只允许一条且必须覆盖整包；代理状态只允许透传，不参与业务判定；隧道属性按标签分组，缺失标签报错；整数和地址属性强制长度；未知属性原样保留；属性数量、单值长度和总长度都有上限；请求与响应分别计算认证器，响应必须用请求认证器和响应内容共同校验。test_radius_attribute_fence.py 现有十五个用例未通过，压零长度、越界、私有属性、双认证器、代理状态、隧道标签、整数长度、地址长度、属性总数、响应认证、未知属性、报文长度、单值上限、总长度和逐层校验。

## 运行方式
```bash
python -m pytest tests -q
```
