# GSB Bugfix Task
## 题面
合同审阅系统上线后，供应商发来的 PDF 成了新的攻击面。预览服务用的解析库默认会执行文档里的动作：一份合同打开时自动跑内嵌脚本，把阅读器的本地接口挨个试了一遍；另一份的打开动作直接拉起外部程序；还有样本在对象流里藏了提交表单和导入数据的动作，表面看只有一页正文；增量更新把恶意版本藏在旧交叉引用表里，我们只读了最新一版，结果预览是干净的、下载下来却是带动作的；嵌入附件被自动释放到临时目录；外部链接动作把内网地址带进了预览请求；页面树里做了个环，递归渲染直接栈溢出；加密文档用空口令就能解开，解开后动作照跑；脚本用十六进制和 UTF-16 转义混写，关键字匹配全部漏掉。pdf_action_fence.py 的 PdfActionFence 要在解析阶段就把这些按住：支持普通交叉引用表和交叉引用流，按最后一组交叉引用定位对象，拒绝指向不存在偏移的条目；遍历文档目录、页面树、注释、命名树和表单，收集打开动作、附加动作、脚本、启动、提交、导入、外部跳转、富媒体和嵌入文件这些条目；动作名和脚本内容先做解码再匹配，十六进制、UTF-16 和转义序列都要还原；页面树和对象引用要做环检测和深度上限；加密文档只接受空口令且要标记为需复核；输出一份动作清单，按对象编号排序，命中禁止项时给出可读原因。test_pdf_action_fence.py 的十五个用例现在全挂，覆盖打开动作、附加动作、对象流藏匿、增量更新、嵌入附件、外部跳转、页面树环、空口令加密、脚本转义、表单提交、富媒体、命名树、交叉引用偏移、对象深度和清单排序。

## 运行方式
```bash
python -m pytest tests -q
```
