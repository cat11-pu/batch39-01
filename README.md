# GSB Bugfix Task
## 题面
团队副本改成自动分装备后，公会频道每天都在吵。需求、贪婪、放弃三种选择没有区分，放弃的人也被拉进随机池；两个人点数相同，系统直接给了先请求的那个；队长分配模式下队长离线，装备悬空；拾取绑定的物品被分给已经拥有的成员；同一件装备在分配完成前被重复加入队列；离线成员仍然参与点数比较，占着名额；轮询分配没有跳过已经拿过的人；金币按人数平均分，除不尽的部分直接丢掉；交易税从总额扣了一次又从每人扣了一次；点数超时后没有默认放弃，队列卡住；分配完成后装备还能被交易。party_reward_split.py 的 PartyRewardSplit 要把分配做成可审计的流程：每个成员对每件装备提交需求、贪婪或放弃，放弃不进入随机池；点数相同按成员编号稳定排序，不按请求到达顺序；队长分配时队长离线则回退到队长指定的代理人，再没有则流拍；拾取绑定检查拥有情况；同一装备编号在队列里只能出现一次；离线成员不参与点数比较；轮询模式跳过本轮已获得者；金币按权重分配，余数按成员编号依次补足；税只扣一次并在明细里列出；点数超时视为放弃；分配完成后进入交易锁定期。test_party_reward_split.py 的十五个用例眼下全部失败，压三种选择、点数平局、队长离线、拾取绑定、重复入队、离线成员、轮询跳过、金币余数、重复扣税、超时放弃、交易锁、代理人、流拍、明细和稳定排序。

## 运行方式
```bash
python -m pytest tests -q
```
