# GSB Bugfix Task
## 题面
发布流水线现在会跑三家静态扫描，结果合并之后安全同学根本没法看：同一个问题在不同报告里出现四五次，路径一个写的是 Windows 反斜杠、一个写的是带协议的文件地址，还有一个把工作目录前缀带上了；指纹字段有的报告给完整值，有的只给一半，代码把半截指纹也当唯一键；同一文件同一行不同列的两个问题被合并成一个；严重级别一家叫错误一家叫高危，映射表漏了两档；被标记为已抑制的问题又冒出来；和基线比较时只比总数不比指纹，修好的问题还在列表里；规则编号大小写不一致被当成两条规则；行号为零的表示整个文件，却被当成第一行；报告里的构件索引指向不存在的条目；消息文本带换行，导出的表格被撑破；多份报告的顺序不同，合并结果每次都不一样。sarif_finding_merge.py 的 SarifFindingMerge 要把多份扫描结果合成一份可复核的清单：先规范化路径，统一分隔符、去掉工作目录前缀、解码百分号转义、区分大小写策略；指纹优先用完整值，缺失时用规则编号、规范化路径、起止行列和消息摘要拼一个稳定值；位置区间重叠超过一半才合并；严重级别按内置映射归一到四档，未知级别落到最低档并标注；已抑制项单独列出，不参与门禁计数；基线比较按指纹集合做差；规则编号统一小写；行号为零单独标记；构件索引先校验再引用；输出按路径、行、列、规则编号稳定排序。test_sarif_finding_merge.py 的十五条断言现在全部失败，覆盖路径分隔符、前缀、转义、半截指纹、列差异、级别映射、抑制、基线、规则大小写、行号零、构件索引、消息换行、多报告顺序、区间合并和稳定排序。

## 运行方式
```bash
python -m pytest tests -q
```
