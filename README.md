# GSB Bugfix Task
## 题面
运维把提权规则从散落的脚本收进统一配置后，审批系统开始给出互相矛盾的结论。同一个用户同时命中允许和拒绝两条规则，代码取了先读到的那条，而规范要求最后匹配的生效；主机名写成通配后缀，匹配时把整个域名都放过了；命令后面带的参数没有参与比较，允许某条命令等于允许它带任意参数；别名定义在引用之后，解析时直接当成未知名称；包含目录的读取顺序不稳定，换台机器结果就变；免密标签写在命令前面却被当成普通参数；运行身份写成空值被当成当前用户；命令里的通配符可以跨目录匹配；大小写不同的用户名被当成两个账号；哈希摘要缺失时仍然放行。sudoers_match.py 的 SudoersMatch 要给出可复核的判定：解析用户、主机、运行身份和命令四段规则，支持别名、包含、标签和否定；匹配按配置顺序进行，最后一条命中的规则生效，否定规则单独标记；主机名只做完整标签匹配，不允许后缀通配吞掉父域；命令参数逐项比较，通配符不能跨越路径分隔符；别名先收集后解析，未定义别名报错；运行身份为空按当前用户处理并标注；免密标签只影响口令要求，不改变是否允许；结果返回命中的规则、生效原因和是否需要口令，快照稳定。test_sudoers_match.py 眼下十五个用例全部报错，压允许拒绝冲突、主机后缀、命令参数、别名后置、包含顺序、免密标签、空运行身份、路径通配、大小写、摘要缺失、否定规则、最后匹配、四段解析、原因输出和稳定快照。

## 运行方式
```bash
python -m pytest tests -q
```
