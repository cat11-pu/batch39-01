# GSB Bugfix Task
## 题面
堡垒机登录策略迁到可插拔认证模块之后，运维改了一行配置就把 root 锁在门外。控制位写成带方括号的跳转形式，解析器只认关键字，整行被当成未知模块跳过；必需模块返回失败，栈却继续往下跑，后面的模块又把用户放进来；充分模块成功之后没有短路，还继续执行更严格的检查；包含指令指向的文件被循环引用，加载直接递归到栈溢出；续行符只处理了行尾反斜杠，行首空白没有合并，参数被截断；注释里的方括号被当成控制位；同一个模块在一行里出现两次，参数互相覆盖；认证、账号、口令、会话四类栈混在一起执行；未知返回码被映射成成功；默认控制位缺失时按可选处理，等于放行。pam_stack_eval.py 的 PamStackEval 要按类型分别求值：解析控制位支持必需、充分、可选、包含和带跳转的方括号写法，跳转目标越界要拒绝；模块按声明顺序执行，必需失败后仍继续收集结果但最终整体失败，充分成功则立即短路，可选失败只记录；包含文件展开后限制深度并检测环；续行、注释、空白按规范处理；未知模块、未知返回码、重复模块都要给出带行号的错误；四类栈各自独立，不能互相污染；结果返回每个模块的返回码、是否短路和最终判定，快照不能被调用方改坏。test_pam_stack_eval.py 里十五项检查当前均未通过，压跳转控制位、必需失败、充分短路、包含环、续行、注释、重复模块、四类栈、未知返回码、默认控制位、行号、深度、参数合并、最终判定和快照隔离。

## 运行方式
```bash
python -m pytest tests -q
```
