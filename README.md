# GSB Bugfix Task
## 题面
依赖扫描接进发布门禁后，安全公告的命中结果一会儿多一会儿少。排查发现版本比较是照着字符串字典序写的，一点零十被排到一点零二前面；预发布版本没有单独排序，正式版反而被判成受影响；公告里写的是开区间加闭区间的组合，代码只取了第一个区间；带通配符的版本被当成普通字符串；构建元数据参与了比较，同一个版本出现两种排序；纪元前缀被忽略；修复版本正好等于当前版本时，边界判断写反；同一个包改名之后，新旧名字的公告没有归并；两份公告描述同一个漏洞，严重级别取了先到的那份而不是最高的；版本号里有前导零和非数字段时直接抛异常；大小写不同的包名被当成两个包；空区间和全集区间没有区分；公告里的受影响范围有重叠时重复计数。advisory_version_match.py 的 AdvisoryVersionMatch 要做版本区间代数：解析版本号时把纪元、主次修订、预发布标识和构建元数据分开，预发布按分段规则排序且低于同号正式版，构建元数据不参与比较；包名统一小写并支持改名映射；区间支持闭开、开闭、通配和并集，多个区间先合并再判定；修复版本边界按左闭右开处理；同一漏洞的多份公告按标识归并，严重级别取最高，受影响包取并集；无法解析的版本进入隔离清单而不是中断整批；结果按包名和版本稳定排序。test_advisory_version_match.py 的十五个用例现在全挂，覆盖字典序、预发布、组合区间、通配、构建元数据、纪元、修复边界、包改名、重复公告、前导零、非数字段、包名大小写、空区间、全集区间和重叠计数。

## 运行方式
```bash
python -m pytest tests -q
```
