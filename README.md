# GSB Bugfix Task
## 题面
新版本的增益系统一上线，数值策划就和程序吵起来了。同一个增益从两个不同来源加上去，一个说要独立叠两层，一个说只刷新时间，代码两种都没做对，最后变成三层；叠加上限写着五层，实际能叠到七层；持续时间取的是最后一次施加的满时长，而不是剩余时间加一截；驱散时先删了最早的那个，结果把不可驱散的核心增益一起带走；免疫状态下仍然被挂上减益，只是图标不显示；属性重算只在施加时做一次，层数变了面板不更新；增益过期后回调没触发，客户端图标一直挂着；时间倒退测试里过期的增益又复活了；同一帧里施加再移除，事件顺序反了；重复施加同一个标识但不同来源，代码直接覆盖，来源信息丢了。buff_stack_policy.py 的 BuffStackPolicy 要按规则表处理叠加：每个增益声明叠加方式，支持刷新时长、延长时长、独立分层和替换四种；层数上限和来源上限分开校验，超出按规则丢弃或替换最弱的一层；持续时间在延长模式下取剩余加增量，不超过配置上限；驱散按优先级从低到高，不可驱散项跳过；免疫检查在施加前，免疫期间不产生层数但记录尝试；层数或来源变化后立即重算属性，并输出变更前后的属性快照；过期、移除、替换都要触发一次且仅一次事件；时间回拨不复活已过期项；同一标识不同来源分别记录。test_buff_stack_policy.py 目前十五项校验均失败，压双来源、层数上限、延长时长、驱散顺序、免疫、属性重算、过期回调、时间回拨、同帧增删、来源覆盖、替换规则、来源上限、事件一次、快照和标识区分。

## 运行方式

