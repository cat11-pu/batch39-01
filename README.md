# GSB Bugfix Task
## 题面
开放平台按租户卖调用额度，最近账单和限流两头对不上。同一个租户在整点前后各打一批请求，两边都算进了新窗口，实际放行量差不多是额度的两倍；批量接口一次带一百条，计费按一次算，额度却按条扣，两边口径不一致；租户突发打了三千个请求，桶里明明有容量，代码却因为上一次被拒而一直拒绝；两台网关的时钟差了三秒，窗口边界各算各的；上游返回失败之后额度没有退回，租户白白损失；重试请求被重复计数；额度为零的租户仍然能进；负数消耗被当成增加额度；未知租户直接放行；窗口状态只存在进程内存里，重启就清零；并发扣减时同一份额度被两个请求同时拿走；等待时间算出来是负数，客户端一直重试。quota_token_window.py 的 QuotaTokenWindow 要把配额判定收成一套：按租户维护滑动窗口，窗口长度、额度、单次最大消耗都可配置；每个请求带权重，扣减是原子的，失败或超时按幂等键退回，同一幂等键只退一次；允许小幅突发但不超过额度的两成；时间取调用方传入的单调时刻，回拨或跳变只记录不扩大窗口；被拒时给出可重试的等待毫秒数，最小为零；零额度、负消耗、未知租户按明确错误码处理；状态要能导出快照并在重启后恢复，快照不能被外部改坏。test_quota_token_window.py 的十五个用例眼下全是红的，覆盖窗口边界、批量权重、突发、时钟偏移、失败退回、重试去重、零额度、负数、未知租户、持久化、并发扣减、等待时间、快照恢复、幂等键和重复启动一致性。

## 运行方式
```bash
python -m pytest tests -q
```
