# GSB Bugfix Task
## 题面
新地图的传送门链接一接进寻路，单位就开始鬼畜。双向链接只配了一个方向，单位过去之后回不来；单向链接被寻路当成双向，路径代价算反；链接两端在相邻导航块上，端点没有吸附到边缘，单位走到墙里；体型大的单位能穿小传送门，体型小的反而被挡；链接的通行代价没有算进总路径，AI 总选传送而不是走路；链接在行走途中被关闭，单位卡在半路；两个传送门终点相同，代价一样时选择不稳定，回放对不上；链接目标落在不可行走区域，寻路仍然返回成功；链接的坐标是格子坐标，寻路用的是连续坐标，换算时少加了半格；链接列表里有重复标识，遍历时进入死循环；传送动画期间单位还能被选中和攻击。portal_link_traverse.py 的 PortalLinkTraverse 要把链接建模成图上的特殊边：每条链接有起点、终点、方向、通行代价、体型限制和开关状态；端点吸附到所属导航块的边缘，连续坐标换算统一加半格；双向链接拆成两条有向边，单向只保留一个方向；寻路时把链接代价和前后步行代价相加，体型不符或关闭的链接不进入候选；目标不可行走时返回失败原因而不是成功；同代价路径按链接标识稳定排序；单位进入链接后锁定移动和受击，动画结束才落地；链接中途关闭时给出中断位置，允许原地停下；重复标识在加载时拒绝。test_portal_link_traverse.py 里十五项检查均未通过，压单向双向、端点吸附、体型、代价、中途关闭、同代价、目标不可走、坐标换算、重复标识、遍历锁、链接开关、失败原因、稳定排序、中断位置和加载校验。

## 运行方式
```bash
python -m pytest tests -q
```
