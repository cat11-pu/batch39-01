# GSB Bugfix Task
## 题面
播放器拖动进度条时总要卡半秒，有时候还会花屏。现在的 seek 只按时间除以固定间隔估算关键帧位置，可变帧率的片源一估就偏；关键帧索引建的时候没有按解码顺序排序，B 帧的显示时间比关键帧晚，索引指到了错误的位置；索引里有空洞时直接返回负一，播放器从文件头重新解码；遇到损坏的关键帧条目，整张索引被丢弃；直播流没有关键帧索引，seek 直接不可用；向前 seek 和向后 seek 用了同一个取整方向，向后总是多解一段；seek 到片尾时越界；时间基是九十分之一秒，代码按毫秒算，时长超过两小时就溢出；多段拼接的片源，每段的时间戳都从零开始，索引没有加段偏移；索引文件比视频新，加载时没有校验版本。keyframe_seek_index.py 的 KeyframeSeekIndex 要建一份可增量更新的索引：从容器里读出每个关键帧的显示时间和文件偏移，按显示时间排序，同时保留解码序号；seek 目标取不大于目标时间的最后一个关键帧，向前和向后共用一套边界规则；索引空洞时回退到更早的关键帧并标记需要多解码的帧数；损坏条目跳过并记录，不影响其他条目；直播模式返回最近的关键帧和可用性标记；时间基统一用有理数换算，避免浮点和大数溢出；多段片源加上每段起始偏移；索引带版本和源文件摘要，不匹配时拒绝加载；查询返回关键帧时间、偏移、段号和预解码帧数。test_keyframe_seek_index.py 里十五个断言均失败，压可变帧率、解码顺序、索引空洞、损坏条目、直播、双向取整、片尾越界、时间基、多段偏移、版本校验、增量更新、预解码帧数、摘要、最近关键帧和稳定排序。

## 运行方式
```bash
python -m pytest tests -q
```
