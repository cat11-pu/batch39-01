# GSB Bugfix Task
## 题面
每日任务的刷新时间在三个地区各错各的：有的玩家凌晨四点就重置，有的要等到早上八点；夏令时切换那天，欧洲区提前一小时刷新；跨时区组队的玩家看到的任务进度一半新一半旧；玩家把设备时区改来改去，重置跟着乱跳；断线三天再上线，只补了最后一天的奖励，前两天的进度丢了；同一秒内重复请求刷新接口，任务被重置两次，奖励领了两份；周常和日常共用一套边界，周一凌晨周常没有重置；月初和月末的边界又单独写了一套；玩家手动改系统时间到未来，领完奖励再改回来，重置记录被覆盖；补发奖励时没有区分已领取和未领取；重置快照里的时间戳用的是本地时间，跨区对不上。daily_reset_boundary.py 的 DailyResetBoundary 要按玩家归属时区计算边界：每个玩家绑定一个时区标识和刷新小时，边界用带时区的时刻表示，存储统一用世界时；夏令时切换按当地规则重算，切换日不重复也不跳过；请求带当前时刻，计算从上次重置到现在的所有边界，逐日补算，奖励按已领取状态去重；同一玩家的并发请求只允许一个执行重置，其余返回当前状态；周常按当地周一、月常按当地一号单独计算，但共用同一套边界函数；检测到时钟回拨或跳到未来时记录异常并拒绝提前重置；补发列表区分已领取、未领取和已过期；快照包含时区、上次边界、下次边界和世界时时间戳。test_daily_reset_boundary.py 的十五条检查当前全部失败，压时区差异、夏令时、跨区组队、改时区、断线补算、并发双发、周常、月常、改系统时间、补发状态、世界时、边界逐日、时钟回拨、过期奖励和快照字段。

## 运行方式
```bash
python -m pytest tests -q
```
