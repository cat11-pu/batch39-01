# GSB Bugfix Task
## 题面
市场部做了个短链跳转服务，上周被白帽子报了一个开放重定向。现在的校验只判断 Location 里有没有出现白名单域名，于是把白名单域名拼在攻击者域名前面这种写法也能过；带用户信息段的地址被当成自家站点；双斜杠开头的协议相对地址直接放行；把斜杠写成反斜杠、把点写成百分号编码，同样能绕；跳转链到第五跳才出国，前四跳都在白名单里，没人看完整条链；307 跳转时方法被悄悄改成 GET；A 到 B 再回 A 的环让抓取任务卡死；从 https 降到 http 没人拦；Location 里带换行还能顺手写响应头。redirect_hop_ledger.py 里的 RedirectHopLedger 要负责整条链的判定：从起始地址开始逐跳解析，每一跳都要独立做协议、主机、端口、用户信息段和路径的规范化，只有协议是 https、主机逐字命中允许集合、端口等于默认值或白名单端口才继续；最多跟八跳，出现环、非 3xx、空 Location 或相对地址解析失败就停在当前跳并记原因；默认拒绝跨站降级和带用户信息段的地址。返回值要给出最终地址、经过的每一跳和终止原因，内部账本不能被外部改掉。test_redirect_hop_ledger.py 的十五项检查现在全部报错，分别压后缀混淆、用户信息段、协议相对、反斜杠、编码变体、多跳跨境、跳数上限、环检测、307 方法、降级、换行注入、相对地址、端口白名单、账本隔离和重复解析一致性。

## 运行方式
```bash
python -m pytest tests -q
```
