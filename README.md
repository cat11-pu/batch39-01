# GSB Bugfix Task
## 题面
内部管理后台的访问控制只认一张地址段清单，最近安全演练被绕了三次。第一次是把点分地址写成一个大整数，校验函数按字符串前缀匹配，直接放行；第二次是地址里带端口和空白，切分逻辑把主机部分截断，落到允许段里；第三次是用协议版本六的映射写法，表面看是版本六，实际指向版本四的回环地址，清单里恰好放行了回环；还有网段写成带主机位的形式，比较时没有先归一，同一段出现两种写法；拒绝规则和允许规则重叠时，代码先命中的赢，而不是拒绝优先；版本六的压缩写法和展开写法被当成不同地址；带区域编号的链路本地地址没有剥掉后缀；零前缀的默认路由被当成合法业务段；地址段合并时把两个不相邻的段拼成一个覆盖更大的段；排序不稳定导致快照每次不同；非法字符被静默忽略；超长前缀被截断。cidr_scope_resolver.py 的 CidrScopeResolver 要先把地址和网段都归一成整数区间，再按拒绝优先、最长前缀优先的次序判定：点分、整数、十六进制、版本六压缩与展开、映射写法都要落到同一表示；主机位必须清零，端口、方括号、区域编号和空白先剥掉；前缀范围要校验；重叠的允许段合并，拒绝段永远压过允许段；默认路由只允许显式开启；结果给出命中的规则编号、归一后的网段和判定理由；快照按数值排序。test_cidr_scope_resolver.py 的十五条断言现在全部失败，覆盖整数写法、端口、映射地址、主机位、拒绝优先、压缩写法、区域编号、默认路由、段合并、排序、非法字符、超长前缀、空白、快照和重复解析一致性。

## 运行方式
```bash
python -m pytest tests -q
```
