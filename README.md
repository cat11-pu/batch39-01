# GSB Bugfix Task
## 题面
实时通道换成二进制序列化之后，一条构造过的消息能让解析器分配几个 G 内存。数组头声明四亿个元素，代码先按声明分配再逐个读，实际数据只有寥寥几字节；映射头同样没有和输入剩余对照；嵌套数组一层套一层，递归层数未设上限；字符串长度前缀是负数编码，解码后被当成超大无符号数；扩展类型的时间戳字段长度不对，仍然按固定长度读；映射里重复键名出现两回，后一条悄悄盖掉前一条；键不是字符串也照收，转成字典时抛异常；保留的类型标签被当成整数继续解析；一条消息解析完后面还有尾巴，代码不管；特殊浮点没有区分。msgpack_depth_fence.py 的 MsgpackNestedCheck 要安全解码：数组和映射在分配前先按输入剩余做上限校验；嵌套层数、容器元素总数、字符串和二进制长度都有上限；扩展类型按声明长度读取，时间戳只接受规定长度；映射键必须是字符串，重复键拒绝；保留标签、非法长度、截断数据都给出带偏移的错误；解析结束必须恰好消耗完输入，多余字节报错；浮点的特殊值单独标记；结果返回对象、已读字节和告警列表。test_msgpack_depth_fence.py 里十五项比对均未通过，压数组超配、映射超配、嵌套层数、负长度、扩展长度、重复键、非字符串键、保留标签、尾随数据、特殊浮点、截断、元素总数、字符串上限、偏移和告警。

## 运行方式
```bash
python -m pytest tests -q
```
