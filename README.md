# GSB Bugfix Task
## 题面
游戏里的语音播报一响，配乐还在自嗨，玩家根本听不清任务提示。现在的闪避处理只是把音乐分组音量乘零点五，播报结束后直接跳回原值，听起来像被人掐了一下；同时有爆炸、播报和队友报点三个闪避源时，只取了最后一个，优先级完全没用；播报还没说完，爆炸结束就把配乐恢复了；闪光弹的耳鸣效果和播报闪避叠在一起，配乐被压到几乎无声；闪避的启动和释放没有时间参数，策划要求的缓入缓出做不出来；配乐本身已经在淡出，闪避又叠了一层，最终音量算错；分组结构里人声也挂在音乐分组下，闪避把人声自己压了；削波检测在闪避之后才做，压完还是爆音；暂停时闪避计时继续走，恢复后配乐直接跳到结束状态；两个播报同时播放，先结束的那个恢复了配乐。ducking_envelope.py 的 DuckingEnvelope 要按优先级和被压分组做闪避：每个闪避源带优先级、被压分组、衰减深度、启动时间、保持时间和释放时间；多个源同时作用时按分组取最深的一次闪避，而不是逐个相乘；高优先级源结束后，若还有低优先级源，恢复到低优先级对应的深度；启动和释放按时间曲线平滑，采样与帧率无关；人声分组独立于音乐分组，闪避不作用于自身；闪避后再做削波保护；暂停冻结所有包络计时；结果输出当前增益、目标增益和每个源的剩余时间。test_ducking_envelope.py 的十五个用例现在全部失败，压多源、优先级、提前恢复、耳鸣叠加、缓入缓出、双重淡出、分组自压、削波、暂停、双播报、释放曲线、深度取最深、帧率无关、增益输出和剩余时间。

## 运行方式
```bash
python -m pytest tests -q
```
